# ADR-054 · `measure.py --adversarial`: its own runner, no spend, a separately dated result (2026-10-27, Claude Code)

**Context.** D-029 left `--adversarial` exiting 3. specs/06 asks for adversarial cases with hypotheses and a separate caught-rate report.
**Options.** Mix adversarial cases into `casos.jsonl` (pollutes recall/fp and the regression baseline); a separate runner.
**Decision.** `tools/measure.py:grade_adversarial` replays each sequence in `evals/adversarial.jsonl` turn by turn through `screen` with accumulated history and a mock Jev, then builds the final `Verdict` via `build_verdict` plus the flag; compares against the expected `manipulation`/`not_legit` outcome. Entries of type `"system"` (attacks on the system itself, not messages) point to their own pytest test and are listed as "in pytest" without running. Metrics: `sequences/passed/caught/manipulations/in_pytest/usd_total`. Only `<date>.adversarial.result.json` is written, never `latest*.result.json` or the case base.
**Why.** Measures the gate without spending credits and without moving classification numbers.
**What would invalidate it.** Running adversarial cases with the real Jev (would need a USD cap like full mode).
