# ADR-036 · One `edge` marker per test for specs/12 edge cases, counted via AST (2026-10-27, Claude Code)

**Context.** T-05b needs `tools/validate_edges.py` to list specs/12 rows with no test, counting `xfail`s too.
**Options.** (a) an id in the test name, clashing with OWASP tests and limiting one row per test; (b) an id in the docstring (free text, any mention counts); (c) a pytest marker `@pytest.mark.edge("A1", "B2")`.
**Decision.** (c), registered in `pyproject.toml`. `tools/validate_edges.py` finds it via `ast` (only literal-argument `*.mark.edge("...")` calls, so a string merely naming it doesn't count) and also reports ids that don't exist in the spec. Rows whose piece doesn't exist yet carry `xfail(strict=True, reason="T-xx")`; `strict` forces whoever builds that piece to write the real test.
**Why.** The marker lives in code, allows several rows per test, and is counted without running pytest.
**What would invalidate it.** Wanting to also verify the test passes, not just exists → switch to `pytest --collect-only` with a plugin.
