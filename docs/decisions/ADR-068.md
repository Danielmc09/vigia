# ADR-068 · Flat `compraventa_*` patterns in the country pack, plus two extra signals: `already_paid` (light) and `extortion` (hard) (2026-10-27, Claude Code)

**Context.** specs/15 asks for `patrones.compraventa` per language and 7 signals; `CountryPack.patterns` is `dict[str, tuple[str, ...]]` and `find_pattern` searches by category.

**Options.** (a) nest (`patrones.compraventa.anticipo`), changing the type and the loader; (b) flat prefixed categories.

**Decision.** (b): `compraventa_contexto` (gate: without sale context and without a role-tagged chat, the module emits nothing), `_anticipo`, `_verificable`, `_rechaza`, `_evasion`, `_identidad`, `_pagado`, `_cobro`, `_presion`, `_amenaza`, in CO.json (es) and US.json (en). Words live in the JSON because the i18n test forbids Spanish in `src/*.py`. `personal_account_only` reuses `pago_personal`. "Offers to verify" = `_verificable` without `_rechaza` on the seller side, and cancels `advance_before_seeing` and `personal_account_only`. `staggered_charges`/`pressure_after_payment` only fire on non-buyer turns from the first turn mentioning a payment onward; a charge requires an amount on the same turn. Beyond the 7: `already_paid` (light, no user text) to pick the "already paid" reply variant (specs/15, A27), and `extortion` (hard) for specs/15's third reply (threats), which had no signal. Reply variants (an `Action`: `dont_pay_sale`, `stop_paying`, `block_and_report`) are chosen in `verdict/build.py:_action` when the label is scam, there is a hard or medium sequence signal (not just `already_paid`), and no hard signal from another source (link, brand, campaign): threat > already paid > not paid.

**Why.** The code chooses the text (rule 14); zero changes to the loader.

**What would invalidate it.** A false positive of `compraventa_contexto` outside this category. Measured 27 Oct (reviewer round 2): of 81 non-`compraventa` cases, 1 fires sequence signals (c-0109, only `already_paid`) and 0 errors.

**Revision 2026-10-27** (reviewer T-06c, MAJOR, `adv-rol-falso-compraventa`): `turns()` used to apply to any text, so a hand-typed `buyer:` line silenced the seller's signals and a typed `seller:` skipped the gate (rule 5: the scammer was choosing which rules run). Roles are now read only if `case.kind == "conversation"`, which `services/ingest.normalize` only sets when `parse_chat` recognizes export headers with date and time; any other case is a single roleless turn. Inside an exported chat, a hand-typed `buyer: …` line has no header: `parse_chat` appends it to the previous message, so it never becomes its own turn.

**Revision 2 2026-10-27** (judge T-06c, incidents c-0119..c-0128): (1) `staggered_charges` now also requires something from the specs/15 sequence besides the post-payment charge with amount: `advance_before_seeing`, `pressure_after_payment`, `personal_account_only`, or a new category `compraventa_condiciona` ("not shipping without that", "before she can travel") — shipping, taxes, or a cage fee after payment alone get no signal. (2) The verify offer only cancels if it appears BEFORE the first money request in the seller's text; a traceable payment (`compraventa_trazable`: card, POS, financing) cancels regardless of position. (3) `personal_account_only` follows specs/15 literally (wallet named + `_rechaza` or `_evasion`); naming a wallet alone no longer triggers it; `_evasion` adds "not answering", "blocked me". (4) `extortion` requires a threat form ("we're reporting you", "I'll report you"); the victim describing having already reported ("I already reported it") doesn't trigger it. (5) `price_below_market` ignores clauses carrying `_anticipo`. (6) "golden" removed from `compraventa_contexto`; the CO reference moved to "golden retriever".

**What would invalidate it.** A real compraventa scam with a single payment method (wallet named, no refusal or evasion) that the analyst also misses.
