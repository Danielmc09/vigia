# ADR-073 · The panel opens with an operator token, not "no login" (2026-10-27, Claude Code)

**Context.** specs/07 said "no login", but the panel spans businesses and the app was then public on Railway.

**Decision.** `GET /panel` requires `VIGIA_PANEL_TOKEN` (≥32 chars, validated at startup) as `Authorization: Bearer` or a `vigia_panel` cookie; compared with `hmac.compare_digest`; no token configured → 404; bad token → 401. Response has `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, and a CSP `default-src 'none'; style-src 'unsafe-inline'` (no script on the page; every value goes through `html.escape`).

**Why.** The panel belongs to the owner; WhatsApp login arrives with T-17b, not needed to gate this.

**What would invalidate it.** More than one operator (then users and sessions).
