# ADR-027 · `Encrypted`/`Hashed` as `NewType` over bytes; still no SQLAlchemy (2026-10-27, Claude Code)

**Context.** specs/16 §3 and D-022 assumed SQLAlchemy `TypeDecorator`s by T-04.
**Options.** Introduce SQLAlchemy now; `NewType`s produced only by `store/crypto.py`.
**Decision.** `Encrypted = NewType("Encrypted", bytes)` and `Hashed = NewType("Hashed", bytes)`; queries stay in asyncpg with plain SQL, and the only path that produces them is `Vault.seal`/`Vault.hash`. The real guarantee is the store receiving plaintext alongside a `Vault` and only writing PII columns with what `seal`/`hash` return; the types mark this but don't enforce it (asyncpg takes raw `bytes` and `store` isn't under `mypy --strict`). What enforces it is the raw-`SELECT` test (`tests/test_cifrado.py`). This revises D-022: SQLAlchemy is dropped, not deferred.
**Why.** With five tables, SQLAlchemy would add a dependency and a second way to talk to the database without removing risk.
**What would invalidate it.** More than ~10 PII tables, or dynamic queries that call for an ORM.
