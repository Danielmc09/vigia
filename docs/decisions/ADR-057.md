# ADR-057 · `--rules-only` does not check regression on `exactitud` (accuracy) or `dudosos` (doubtful) (2026-10-27, Claude Code)

**Context.** specs/06 asks that no metric drop > 2 points, and D-029 kept that check in rules-only mode too. But without an analyst the code can never say `legitimo` (specs/05 rule 4): every legitimate case added to the set becomes one more `dudoso`, lowering accuracy and raising doubtful with nothing actually getting worse. Incidents c-0085..c-0088 did exactly that (accuracy -2.6 points) with recall and fp unchanged.
**Options.** (a) live with it and keep legitimate additions small (deforms the set, as D-056 had to); (b) hand-regenerate the baseline (forbidden); (c) exclude those two metrics from regression in rules-only mode specifically.
**Decision.** (c). `tools/measure.py:RULES_CEILING` is applied in `regressions(metrics, baseline, full=False)`; full mode still checks all four. `recall_estafa` and `fp_legitimo` stay under regression in both modes, and `manipulacion_legitimo` stays under its hard ceiling (D-056). Deviation from specs/06, noted in ESTADO.md.
**Why.** Accuracy and doubtful-rate in rules-only mode only measure the ceiling of what rules alone can do without an analyst, not whether a rule change made things worse.
**What would invalidate it.** A new rule able to produce `legitimo` without an analyst (e.g. an official-domain allow-list that closes as legitimate) → `exactitud` goes back to being meaningful there and regression is restored.
