# ADR-037 · Rejections as data, and attachment limits without a decoder yet (2026-10-27, Claude Code)

**Context.** specs/12 A5/A6 require a corrupt or 0-byte image to be `Rejection{INVALID_ATTACHMENT}` and a >10MB one to be cut off before a full download. No downloads exist yet (T-11..T-13) and no Pillow (D-033).
**Options.** Wait for T-12; validate with Pillow (new dependency); validate via magic bytes and cap the stream by size.
**Decision.** `domain/rejection.py` defines `Rejection(error_code, message, retryable)` per specs/09, with English error codes (`INVALID_ATTACHMENT`, `TOO_LARGE`). `domain/attachment.py` has `MAX_ATTACHMENT_BYTES = 10MB`, `check_image` (empty or non-JPEG/PNG/GIF/WebP header), and `read_capped`, which stops reading at the first chunk that crosses the cap. `IncomingMessage` moves from a loose `attachment_ref`/`mime` to `attachments: list[Attachment]` (specs/12 A4: several images form one case).
**Why.** No dependencies, and the channel adapter (T-10/T-11) only has to hand it `aiter_bytes()`.
**What would invalidate it.** Truncated images with a valid header reaching SAM → T-12's decoder rejects them.
