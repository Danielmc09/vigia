# ADR-111 · Showing signal names is a matter of role (operator yes, owner no), not of screen; the forbidden-terms grep covers WhatsApp and the alert (2026-10-31, Angel + Claude Code)

**Context.** While syncing specs/10 with the code (task M), a real contradiction surfaced, not just drift: §7 banned any pattern or signal name on the client and assumed a `tests/test_owasp.py` A05 test that greps the HTML/bundle against a forbidden-terms list. That test never existed — A05 only covers headers and the absence of docs in prod. Meanwhile the operator panel (D-073, behind `VIGIA_PANEL_TOKEN`) already shows `lookalike`, `brand_off_domain`, and the rest as chips in the `signals` column (`panel.py:_chips`), because that's the evidence that makes the verdict credible to the judges.

**Options.** (a) hide signal names in the operator panel too, to follow §7's letter as written. (b) write the forbidden grep and apply it to the panel as well. (c) split the rule by ROLE: the operator panel may show internal taxonomy because it's behind the token (D-073); what's forbidden is exposing it in text that any regular user reads (WhatsApp replies, team alert), even if signing up is required first.

**Decision.** (c). Signing up a business is open — anyone can write "hi, Tienda CO" — so WhatsApp replies and the team alert are public surface even though there's a signup step. The panel and `panel.js` are not, because they require the operator token. A forbidden-terms grep (`MODEL_API_KEY`, signal names) is added over those two surfaces in `tests/test_owasp.py` (new A05), never over the panel.

**`/caso` stays out of the grep.** It's a structured contract for tools (`medir.py`, evals, tests): it returns the `Verdict` with `signals[].type`, and `test_app.py` checks those types. It is not free-form text aimed at a person.

**Condition (not a footnote).** `/caso` is public and tokenless. Today that exposes nothing because there is no hosted instance (D-112): it only lives on the machine of whoever runs `make demo`. **If it is ever deployed on a reachable host, `/caso` must go behind a token like the panel**, for two reasons:

- the signal taxonomy comes out in the JSON;
- without a token it's free model spend for anyone. `judge_text` calls the gate judge, which outside `dev` is `SparkJudge` if `MODEL_API_KEY` is set (`services/judge.py`), even when the analyst is `None`.

Deploying without that token breaks this decision. It also goes into "what the system does NOT cover" in the threat model (T-22b). specs/10 §7 is rewritten: the distinction is by role, not by screen, and a note is left for T-17b (owner view): if it reuses the verdicts-table render, it must filter internal names out before showing them to a business — D-073's permission belongs to the operator, it isn't inherited.

**Why.** (a) would hide from the operator the evidence they need to trust the verdict during the video, for no gain: the operator already has the token, they aren't who the taxonomy needs protecting from. (b) without a scoped surface would have blocked the panel itself. Role, not screen, is what defines who can see what — the same principle D-073 already uses to separate the panel from the public API.

**What would invalidate it.** T-17b actually sharing the table component between operator and owner without the filter this calls for — then the bug would be real, not just a test gap. The app ending up on a reachable host with `/caso` still tokenless.
