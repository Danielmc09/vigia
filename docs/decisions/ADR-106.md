# ADR-106 · A forward repeats the verdict if under 6 hours old; older, it's re-analyzed (2026-10-31, Claude Code)

**Context.** Angel forwarded the same voice note at 9:39 and 9:46 and both times got only "Already reviewed this message." Root cause wasn't the wamid (each forward gets a new one and `save_case`'s `message_id` dedupe never tripped); it was the permanent byte-hash claim for media (`_first_media`, D-083): an already-seen file stayed duplicate forever and the reply said nothing. Forwarded text, conversely, gets a new wamid, was never deduplicated, and spent model money every time. A saved verdict ages: case 11 (Oct 31) came out with no brand because it predates D-104, and repeating it forever would repeat that mistake.

**Options.** (a) always repeat the last verdict — free, but freezes already-fixed bugs. (b) always re-analyze — correct, but spends model money on back-to-back repeats of the same thing. (c) repeat if recent, re-analyze if old. (d) repeat while the rules version/deploy hasn't changed.

**Decision.** (c), threshold `FRESH = 6h` (`services/ingest.py`). The content key is `media:<sha256 of the downloaded bytes>` or `text:<whitespace-collapsed text>` (`domain/case.content_key`), stored as `vault.hash("<business_id>:<key>")` in `cases.content_hash` (migration 0011): with the business id inside, as in D-083, the table doesn't correlate businesses and the lock doesn't block a different business receiving the same campaign. `store.fresh_verdict` takes a `pg_advisory_xact_lock` on the hash, so a concurrent copy waits for the first to commit its verdict in the same transaction, then returns the newest verdict under 6 hours, decrypted with the business's vault. The reply is `case.repeat` ("Already reviewed on <dd/mm at HH:MM>:") plus the same `whatsapp_message` (verdict, signals, what to do, official channel, case number), with no model or reader called. Media is hashed before paying for any read. `_first_media` and its claim are removed: D-083 is superseded at that point; D-083's semaphore stays. A provider redelivery of the same wamid still comes out as `case.duplicate` via `save_case`.

**Why 6 hours.** Covers "twice in a row" and a campaign wave reaching several team members the same morning, when repeats are most common. A deployed rule fix reaches forwards within hours, not days. Re-analyzing costs about $0.004/case (Oct 31 run: $0.750/205): erring toward "old" is cheap. The time is shown in Colombia time for every business (`COLOMBIA` in `channel/panel.py`), flagged with a ponytail note as a shortcut.
