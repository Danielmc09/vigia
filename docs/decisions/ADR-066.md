# ADR-066 · Exported chat as role-tagged text in `domain/conversation.py`; seller role by amount heuristic (2026-10-27, Claude Code)

**Context.** T-06c, specs/15 asks for a parser of WhatsApp exports tolerant of iOS/Android, anonymizing the user and leaving the other side as "seller" (`ingesta/conversacion.py`). Signals only see `domain`, and `Case` has no turn field.

**Options.** (a) a new `Case.turns` field (touches the encrypted schema and `save_case`); (b) the chat is stored as rendered `Case.text`, one `seller|buyer|other: <message>` line per turn, and signals re-read it via `turns()`.

**Decision.** (b). `parse_chat` (iOS header `[d/m/y, h:m(:s)( AM/PM)]` or Android `d/m/y h:m -`; headerless lines continue the previous message; system notices excluded), `render_chat` (masks the buyer's name words ≥3 letters as `buyer`; past `MAX_TURNS = 300` keeps the last 300 plus earlier turns with amounts, specs/12 A28), and `turns`. The parser lives in `domain` because it's used by `services/ingest.normalize` and, via `turns`, by `signals/sequence.py`. Seller = whoever writes more lines with amounts (`domain/text.py:amounts`); tie → whoever didn't speak first (the buyer usually opens). `kind = "conversation"` only if the text starts with a header and has ≥2 turns; a single message stays `text` and counts as one roleless turn (seller side).

**Why.** No migration, no new type crossing layers, the analyst gets the same already-anonymized text.

**What would invalidate it.** A real chat where the buyer quotes more prices than the seller (ask the member once, via `origen`) or an export format that doesn't match (A29, not implemented).

**Revision 2026-10-27** (judge T-06c, MAJOR 3, incident c-0127): the victim writes more amounts than the seller ("I already transferred the $300,000", "I don't have $250,000 more") and the amount heuristic classified her as `seller`, silencing `staggered_charges`/`pressure_after_payment` and leaving her name unmasked.

**Options.** (a) keep amounts, break ties by order; (b) count who ASKS for money; (c) ask the member (`origen`, T-10).

**Decision.** (b). `render_chat(chat, asks)` takes a predicate; `services/ingest.normalize` passes `signals/sequence.asks_payment` with the business's country pack (the domain layer doesn't see packs). A line asks for money if it carries `compraventa_presion`, or if it isn't a question (no trailing `?`), doesn't describe a completed payment (`compraventa_pagado`), and carries `compraventa_anticipo`, `pago_personal`, or `compraventa_cobro`. Seller = more asking lines; tie → more amount lines → didn't speak first. Also (rule 19), ALL speakers' names are masked by role in the text, not just the buyer's: if roles flip, the member's name still never appears in clear.

**Ceiling.** A buyer quoting what they were asked ("he's asking for an advance via Nequi") counts as asking too; a common word in the seller's name ("Criadero X") also gets masked in the text and can silence `compraventa_contexto`.

**Revision 2 2026-10-27** (reviewer T-06c, MAJOR, incident c-0129): "seguro" ("sure"/"insurance") is inside `compraventa_cobro` and `asks_payment` counted it without an amount, so a buyer answering "Sure, I'll confirm tomorrow" twice could out-score a seller who asked for an advance once.

**Decision.** One single definition of a charge, `signals/sequence.py:_charge` = `compraventa_cobro` + `amounts` on the same line, used by both `asks_payment` and `staggered_charges` (which already required an amount). `render_chat` no longer defaults `asks`; the caller decides — without a country pack, `ingest` passes `domain/conversation.never` (roles by amount and order only).

**Revision 3 2026-10-27** (judge T-06c, round 3, incidents c-0136 and a masking test): (1) `asks_payment` drops every line where the buyer speaks (`sequence._narrates`): a question (`?` or `¿`) only counts if the line also describes a payment (reviewer round 4, c-0138), a completed payment, or a first-person act/words (new category `compraventa_narra`: "I'll pay him", "I told him") — unless it also carries `compraventa_presion`. (2) Masking compares diacritic/case-folded text; the speaker's full name and every word ≥3 letters is masked, except trade words that `signals/sequence.is_trade_word` recognizes from `compraventa_contexto` (e.g. "kennel", "motorcycle"). Without a pack, nothing is exempted (rule 19: when in doubt, mask everything).

**What would invalidate it.** A real chat with the member's name in clear (incident, security bug).
