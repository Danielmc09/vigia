# ADR-050 · `build_verdict(case, evidence, pack)`: fusion inputs travel as `domain.analyst.Evidence` (2026-10-27, Claude Code)

**Context.** T-07's reviewer flagged that `manipulation_detected` (the gate's flag, T-08) was traveling through `case.context`, an untyped dict also used to fill the eval set. Adding it as a parameter would cross the project's 4-argument limit (ruff PLR0913).
**Options.** Raise the limit; a keyword-only parameter (still counts for ruff); a small input object.
**Decision.** `Evidence(signals, analyst, manipulation_detected)` in `domain/analyst.py` (shared by `app.py`, `tools/measure.py` and `verdict/build.py`, hence in `domain`). Verdict assembly moves from `verdict/fusion.py` to `verdict/build.py`; `fusion.py` keeps `fuse`, rules 1-5, and `soften_citations`. Both `measure.py` and `POST /case` call `build_verdict`, so there's no second path that can diverge.
**Why.** One typed input object instead of an ever-growing parameter list.
**What would invalidate it.** The gate judge returning more than a boolean (e.g. a score that modulates confidence) → `Evidence` grows a field, not a new parameter.
