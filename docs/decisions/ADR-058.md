# ADR-058 · Analyst loop on chat completions with `tools` + `json_schema` together; `web_search` via `/v1/responses` (2026-10-27, Claude Code)

**Context.** specs/03 asks for a tool-using agent that ends in a `Verdict` with schema. T-02 verified separately that `tools` and `json_schema` work together on chat completions, and that `web_search` only works on `/v1/responses` (400 on chat completions).

**Options.** (a) run the whole loop on `/v1/responses` without verifying function calling there; (b) chat completions with both features together, with search as one more function the code resolves via a separate Responses call; (c) two phases (investigate without schema, then one call with schema).

**Decision.** (b). A real call (specs/03 "Verified" 3c, `tests/fixtures/meta/chat_tools_json_schema.json`, $0.001225) confirmed 200 with both together. `src/vigia/analyst/tools.py:TOOL_SPECS` declares `web_search` as a function; `services/analyst_tools.py:_web_search` runs it via `SparkClient.web_search` (Responses, `search_context_size: low`, `max_output_tokens` 200) only if the gate said `triage == "investigate"`, capped at `MAX_SEARCHES = 2` per case (the 3rd returns `LIMIT_REACHED` as data).

**Why.** One message format for the whole loop, strict schema on every turn, and search cost only when needed.

**What would invalidate it.** Meta enabling `web_search` on chat completions (switch to native tool call) or the combination starting to fail (fall back to (c)).
