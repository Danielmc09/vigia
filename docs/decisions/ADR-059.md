# ADR-059 · Spark adapter over `httpx`, no SDK, with per-client accumulated cost (2026-10-27, Claude Code)

**Context.** The `openai` SDK is not installed and D-024 forbids new dependencies without approval; `model/jev.py` already uses sync `httpx` (D-052).

**Decision.** `src/vigia/model/spark.py:SparkClient` with `complete(ModelRequest) -> ModelTurn | Rejection` and `web_search(query)`. `reasoning_effort = "minimal"` (Spark's floor; `none` is a 400). Per-call pricing with `usage_usd` at verified prices ($1.25 / $0.15 cache / $4.25 per 1M; +$0.0025 per `web_search_call`). The client accumulates `usd` and `tokens`; `tools/measure.py:with_analyst` bills each case by the difference. Any HTTP or shape error → `Rejection("MODEL_UNAVAILABLE", retryable=True)`, never an exception; the key only comes from `Settings.model_api_key` (`MODEL_API_KEY`). The port types (`ModelRequest`, `ModelTurn`, `ToolCall`) live in `domain/analyst.py` so `analyst/` and `model/` never import each other.

**Why.** Reuse the existing httpx pattern, avoid an unapproved dependency, keep the port in domain so adapters stay independent.

**What would invalidate it.** T-10's async webhook (switch to `httpx.AsyncClient`) or the SDK being approved.
