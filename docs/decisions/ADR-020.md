# ADR-020 · PII encrypted in the application with a per-business key; hashes for search (2026-10-27, Angel)

**Context.** The database stores people's phone numbers, emails, names, messages and attachments.
**Options.** Plaintext + RLS; pgcrypto; application-level encryption (AES-GCM) with a per-business DEK under a KEK, plus HMAC for search.
**Decision.** The third, from T-04.
**Why.** The database and backups never see plaintext; deleting a business means deleting a key; a record can't be moved between businesses (AAD); verified by a raw `SELECT` in `make security`.
**What would invalidate it.** Nothing; it's a requirement.
