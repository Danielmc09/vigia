# ADR-038 · Clean text before patterns and URLs: NFKC and stripped format characters (2026-10-27, Claude Code)

**Context.** specs/12 A19 requires NFKC normalization and removing zero-width characters before patterns and URLs. A `​` inside a domain was splitting it in two, and an RTL override could hide text. Also, Cyrillic-lettered hosts weren't extracted because the URL regex only accepted `[a-z0-9-]`.
**Options.** A fixed list of invisible characters; strip the whole Unicode `Cf` (format) category; leave homoglyphs to the confusables map in `signals/urls.py`.
**Decision.** `domain/text.py: clean_text` applies NFKC and strips every `Cf` character (zero-width, joiners, bidi marks, BOM, soft hyphen); `ingest.normalize` runs it on text or email body before extracting URLs. What counts as a host is decided by D-039. The text stored on the case is already clean. `text_too_long` (A2) is the mild `text_too_long` signal when text exceeds `LONG_TEXT_CHARS = 4000`, the spec's number.
**Why.** `Cf` covers invisible characters not on some hand-made list, and NFKC already folds full-width forms.
**What would invalidate it.** Emojis with ZWJ (family, flags) getting split apart. Doesn't affect signals, but if shown to the user the ZWJ between emojis must be preserved.
