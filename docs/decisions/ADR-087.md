# ADR-087 · An empty environment variable means unconfigured; required ones fail (2026-10-30, Claude Code)

**Context.** T-22c (`make demo`). `.env.example` ships ten optional variables empty (`MODEL_API_KEY=`, `METRICS_TOKEN=`, `SENTRY_DSN=`, ...) and compose passes `${VAR:-}`. Pydantic turned `""` into `SecretStr('')`, which is not `None`: factories never degraded, and `METRICS_TOKEN=` blocked startup on length (found by a clean clone).

**Options.** (a) global `env_ignore_empty=True` — rejected by the reviewer: `VIGIA_MODO=""` silently fell to `dev` (docs exposed on Railway, which has no compose). (b) a validator on `model_api_key` only — insufficient: a clean `make demo` clone still failed on `METRICS_TOKEN=`. (c) a `before` validator on every field: `""` → `None`.

**Decision.** (c). An empty optional field becomes `None` (no panel, no metrics, no Sentry, rules-only mode). A required field or a `Literal` (`VIGIA_MODO`, integers, DSNs) gets `None` and fails instead of falling back to its default — no silent fall to `dev`. `VIGIA_MODO=prod` also rejects the public example keys (`EXAMPLE_SECRETS`, rule 19).

**What would invalidate it.** A field needing to distinguish "empty" from "absent" (e.g. a meaningfully-empty list).
