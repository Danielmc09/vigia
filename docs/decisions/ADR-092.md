# ADR-092 · A misspelled command gets its usage string back; 6-word / 11-digit thresholds (2026-10-30, Claude Code)

**Context.** `equipo <tel> Luis` got no reply and created no member (`inc-equipo-sin-respuesta`): failing the grammar, the message fell through as a plain case. The literal recorded text does match the earlier regex, so the likely cause is the phone's shape as received (no `+`, with bidi marks U+202A/U+202C WhatsApp inserts when copying a contact). Angel asked: accept the number with or without spaces/`+`, and a reserved word with broken formatting should get the correct usage string, never an analysis.

**Options.** (a) every message starting with a reserved word gets a usage reply — a real forwarded message starting with "Security team at Bancolombia: ..." would never be analyzed, a silent false negative. (b) only if the message is short (≤6 words) and has no link; longer stays a plain case. (c) a separate "attempt" regex per command — seven more patterns to maintain.

**Decision.** (b). `misused_command` in `services/commands.py` replies `usage.<command>` for argument-taking commands (team, supplier, my email, code, transfer, confirm, cancel, scam confirmed). Text is cleaned with `clean_text` (NFKC, strip `Cf`) before parsing. The phone accepts optional `+`, spaces, `-`, `.`, parentheses; `_team` requires ≥11 digits (`MIN_PHONE_DIGITS`), because `team <member's number>` without a country code would silently enroll `+<member's number>` (Belgium). The usage reply never queries the database: it doesn't reveal whether a number is enrolled.

**Why.** One rule and one threshold instead of a parallel grammar. A well-formed command never reaches here (handled by `parse_command`); six words covers typical broken attempts (`team Luis <member's number>`, `confirm 14x`) and almost no complete scam message, which carries more text or a link.

**Note (reviewer).** An employee misspelling an owner-only command (`team Luis`) gets `usage.team`, not `command.owner_only`: usage doesn't check role or the database. Typed correctly, it gets `owner_only`. Accepted: it doesn't leak who is enrolled.

**Accepted risk (judge).** A short scam with no link starting with a reserved word ("Confirm transfer, reply YES") gets `usage.confirm` and is never analyzed. No eval watches this yet; a real occurrence becomes an incident and lowers the threshold or requires an id-shaped argument.

**What would invalidate it.** An eval or incident with a forwarded scam ≤6 words starting with a reserved word; a third country with <11-digit numbers including country code (then the prefix comes from the country pack).
