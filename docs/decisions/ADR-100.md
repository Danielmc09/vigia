# ADR-100 · Unknown shorteners by heuristic, no medium signal if they don't redirect (2026-10-31, Claude Code)

**Context.** `ma.sv` wasn't in `SHORTENERS`; the list will never be complete. But a known shortener that can't be followed is `unresolved_shortener` (medium), and two distinct mediums mean SCAM.

**Options.** (a) list only. (b) a heuristic treating anything short-looking as a shortener, with a medium signal if it doesn't resolve. (c) a heuristic that only acts if it actually redirects elsewhere.

**Decision.** (c). Known + unresolvable = medium (unchanged). Heuristic (registrable label ≤3 letters, not an IP, a 4-12 char single alphanumeric-token path, no query) + redirects = the destination is judged; + doesn't redirect or fails = normal host signals, NO medium: a short domain that doesn't redirect isn't a shortener. `ma.sv` only enters the list once the resolver is actually injected (adding it earlier made the case worse). Accepted cost: the server HEADs short attacker domains, which learns the link was viewed.

**What would invalidate it.** False positives on legitimate short domains with single-token paths, or shorteners with longer paths.

**Deviation (Oct 31, implementation).** `ma.sv` does NOT enter `SHORTENERS`: in production it replies HEAD 405 and GET 200 with no `Location` (redirects via JS or body, never read). Listing it would make it a permanent medium — worse than today. Covered by the heuristic: if it ever redirects via header, the destination gets judged; otherwise, host signals with no medium. The real Cruz Verde case with `ma.sv` stays doubtful in production until there's another way to resolve it.

**Addendum (Oct 31, judge FAIL → incidents c-0218, c-0219).** The heuristic, as written, replaced ALL of the short domain's host signals with the destination's: `tcc.top` (Bancolombia lookalike, hard) and `etb.co` (ETB lookalike, hard) lost their hard signals whenever the attacker made the link redirect to an official domain. Context: the short domain IS the attacker's, not a neutral shortener; D-098 forbids the resolved URL from absolving anything beyond the legit guard, and this violated that.

**Options.** (a) always replace with the destination; (b) union host and destination signals; (c) only unroll if the raw host carries no medium or hard signal.

**Decision.** (c). `url_signals` computes `_host_signals` first; the heuristic (`_unrolled_by_shape`) is only attempted if those signals are all `light`. A dirty host is never unrolled by heuristic: its hard/medium signals decide alone.

**What would invalidate it.** A legitimate short domain with a medium host signal (e.g. `suspicious_tld` on a normal ccTLD) that genuinely redirects to an official site; today it stays doubtful instead of absolved — would need evaluation as an incident.
