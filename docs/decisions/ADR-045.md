# ADR-045 · Policy as a closed `TOOL_GRANTS` map; the prompt describes, the code permits (2026-10-27, Claude Code)

**Context.** T-07 must separate what the T-09 analyst's prompt can ask for from what actually executes (the agentes-sas pattern: "the prompt describes, policy permits, a refusal comes back as data").
**Options.** Allow anything the analyst asks and validate per-call with a repeated `if`; a hand-reviewed enum of "dangerous actions"; a closed map `TOOL_GRANTS: dict[str, Literal["reversible", "irreversible"]]` built from two sources (a fixed `REVERSIBLE_ACTIONS` tuple and `get_args(EscalationAction)`, the domain type) covering exactly their union, checked by a test (`test_tool_grants_is_closed`).
**Decision.** The third, in `policy/actions.py`. `may_execute(action, origin, escalation, now) -> Rejection | None` is the only gate (a refusal is always a `domain.Rejection`, never a bare `bool` or `KeyError`; an unmapped action returns `UNKNOWN_ACTION`). A `"reversible"` action always runs; an `"irreversible"` one needs a confirmed, unexpired `Escalation`, and the `local`/`eval` channel never executes one even if confirmed (proven by a parametrized test over both conditions x every action). `confirm`/`cancel` return the new `Escalation` or a `Rejection`; only the owner can confirm/cancel, and a confirmed escalation only unlocks its own action.
**Why.** A closed, test-checked map can't silently reopen; scattering the `if` across callers is the pattern that gets forgotten in the next channel.
**What would invalidate it.** A "reversible" action turning out to have a real-world cost in production (e.g. a paid alert channel) → move it to `EscalationAction`, enforced by the closure test.
