# ADR-052 · Jev adapter: synchronous `httpx`, 2s timeout, two questions, any error falls back to mock (2026-10-27, Claude Code)

**Context.** T-02 verified `POST https://api.typesafe.ai/v1/systemone` with one question per call (`noul` 251ms, `choice` 185ms).
**Options.** One call with both questions (unverified); two verified calls.
**Decision.** `src/vigia/model/jev.py:JevJudge`, two calls (`manipulation:noul`, `triage:choice`), `TIMEOUT_S = 2.0` per question (~8x the measured median), and `(httpx.HTTPError, ValueError, KeyError, TypeError)` fall back to `MOCK_ANSWER` with a warning when there's no key. `Settings.jev_backend` (`JEV_BACKEND`, default `mock`) and `jev_api_key`; `make_judge` returns the real one only with `real` + a key.
**Why.** Jev is auxiliary; a case never waits more than ~4s on it, nor fails because of it (C10). No new dependency (`httpx` already present).
**What would invalidate it.** Confirming one call accepts both questions (merge them, with a `ponytail` comment in the code), or the async webhook (T-10) needing `httpx.AsyncClient` (today `/case` calls it synchronously inside an async handler).
