# ADR-035 · Brand only in the path: medium signal `brand_in_path`, not hard (2026-10-27, Claude Code)

**Context.** T-06's judge found `brand_off_domain` (hard, the analyst can't override it) firing on aliases that appear in a path as a common word or payment method: `tiendaropa.com.co/checkout/pse`, `payu.com.co/pse`, `.../promo/dale-click`, `.../movil/claro`, `paypal.me/juan`. A real supplier PSE payment link ended up alerting the whole team (incidents c-0048, c-0049, c-0050).
**Options.** Exclude short aliases (<=5 letters), but "claro", "nequi" and "dale" are still common words; a hand-maintained list of generic aliases per brand; split host from path.
**Decision.** A brand in the host (whole token or hyphen-free label, including in a foreign subdomain) is still hard `brand_off_domain`; a brand appearing only in the path becomes medium `brand_in_path` (needs another medium signal of a different type to become a scam, per D-034). `paypal.me` is added to PayPal's official domains in `US.json` (verified: `https://www.paypal.me/` 301s to `https://www.paypal.com/paypalme/`).
**Why.** In the host, the brand is the domain owner's choice to impersonate; in the path, anyone can write it for legitimate reasons. Recall unchanged (0.667), fp_legitimo 0 over 50 cases.
**What would invalidate it.** Real scams with the brand only in the path and no other medium signal ending up doubtful → add an incident eval and consider combining `brand_in_path` with a login form signal.
