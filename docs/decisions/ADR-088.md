# ADR-088 · The `/panel?token=` link is exchanged for a cookie (2026-10-30, Claude Code)

**Context.** T-22c. `make demo` opens the panel in a browser, but D-073 only accepted `Bearer` or the `vigia_panel` cookie, and nothing set that cookie; a clean clone got 401.

**Options.** (a) print a `curl` with Bearer — opens nothing in a browser. (b) a login form — more code, another route. (c) `GET /panel?token=X` validates in constant time, replies 303 to `/panel` with an `HttpOnly`, `SameSite=Lax` cookie, token leaves the URL.

**Decision.** (c). The token only lingers in browser history and logs, and `telemetry.scrub` replaces `token=…` with `token=***` on every log line, including `uvicorn.access`. The cookie has no `Secure` flag because `make demo` uses `http://localhost`.

**Revision (T-22e).** The cookie gets `Secure` when `X-Forwarded-Proto` (or the scheme) is `https`: Railway terminates TLS at its proxy and the app sees `http`. Trusting the header can only harden the cookie, never weaken it. `make demo` URL-escapes the token: a base64 `+` was arriving as a space and causing 401.

**What would invalidate it.** More than one operator (switch to sessions, as D-073 anticipated), or a proxy in front that logs the URL before the app sees it.
