# ADR-025 · PII encryption with `cryptography` (AES-256-GCM) and stdlib HMAC-SHA256 (2026-10-27, Claude Code)

**Context.** D-020 requires per-business encryption and keyed hashes for search; the stdlib has no AEAD.
**Options.** `cryptography` (AESGCM); PyNaCl (secretbox); `pgcrypto` in the database.
**Decision.** `uv add cryptography` (50.0.2). AES-256-GCM with a random 12-byte nonce (blob = nonce‖ct‖tag) and AAD `"<business_id>|<table.column>"`; each business's DEK is wrapped under `VIGIA_KEK` with AAD `"dek|<business_id>"`; search via `hmac.sha256(PII_HMAC_KEY, normalized_value)`. All in `src/vigia/store/crypto.py`.
**Why.** `cryptography` is the maintained reference library; `pgcrypto` would put the key in queries (and Postgres logs); the AAD prevents moving an encrypted value between businesses or columns without failing.
**What would invalidate it.** A managed KMS on Railway (the KEK would wrap there instead), or an unpatched CVE in `cryptography`.
