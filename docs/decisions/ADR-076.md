# ADR-076 · Images: QR in code via zxing-cpp + Pillow, Spark reads text before signals, SAM only as a fallback (2026-10-27, Claude Code)

**Context.** T-12 needs screenshots with QR and logo; D-033 left `decode_qr` empty. Decoder options: `pyzbar` (needs system `zbar`, absent), `opencv` (heavy, pulls numpy), `zxing-cpp` (wheel with no system libs, reads PIL images directly). Flow options: (a) SAM and a `decode_qr` tool for the analyst; (b) a code step before signals, mirroring D-070/D-071.

**Decision.** Dependencies `zxing-cpp` + `Pillow` (installed by Angel), and (b). `services/transcription.image_reader(read, segment)` builds a `Transcriber`: Spark `read_image` (chat with `image_url`, strict schema `{text}`, 1000 tokens, 20 s) puts visible text into `Case.text` (`kind` stays `image`); the QR is decoded in `signals/qr.py:decode_qr` over the whole image and, ONLY if none is found, SAM 3.1 is asked (`model/sam.py`, `/v1/responses` SSE, $0.0025/image) for `"qr code"` boxes, each crop decoded (`domain/image.py:crop`: box scaled to real size, 15% margin, grayscale, upscaled to ~400px). QR links travel separately in `Case.qr_urls` (never mixed into the text the user sees) and `detect` runs `qr_signals` on them (same URL rules with `origin="qr"` + medium `qr_to_unofficial_domain`). For the analyst, a `crop(prompt)` tool with a closed list `{"logo","qr code","button"}`, image cases only; returns boxes and QR links, never model text to the user (rule 14). No separate `decode_qr` tool: the QR is already decoded upstream. `image_phash` stays in `domain/knowledge.py`, not wired to `knowledge_signals` yet. `--solo-deterministas` skips images without `texto` (`NO_IMAGE`), like audio and PDF.

**Why.** Hard signals need the QR link before deciding if the analyst is needed; SAM as fallback only costs when the QR can't be read whole.

**What would invalidate it.** Real screenshots with a QR that zxing can't read even cropped, or accuracy for `tipo=imagen` < 0.80 with Angel's real screenshots.
