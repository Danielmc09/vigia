# ADR-099 · Short-link unroller in `vigia.net`, with anti-SSRF guards (2026-10-31, Claude Code)

**Context.** The `Resolver` port existed in `signals/urls.py` but nobody implemented or injected it: not even `bit.ly` was resolved. Following a link an attacker chose, from the server, is an SSRF primitive.

**Options.** (a) `httpx` with `follow_redirects=True`. (b) hop-by-hop following with validation before each hop. (c) an external unshorten service (new dependency, leaks the link to a third party).

**Decision.** (b), a new package `vigia.net` (adapter; `signals` never imports it; satisfies all three `.importlinter` contracts). Max 3 hops; a shared 1.5s TOTAL budget; HEAD, falling back to a closed-stream GET on 405/501, body never read or sent to a model. Before each hop: scheme http/https, port 80/443, no user/password in the URL, and every IP the DNS resolves to must be `is_global` and not multicast (blocks private, loopback, link-local/169.254.169.254, CGNAT, reserved ranges; `is_global` lets multicast through, hence the extra check). No cookies (cleared before each hop), `trust_env=False` (no proxies, no .netrc), no header forwarding. Returns `Unrolled` (domain type): original, chain, final, hop count; the chain feeds the signal's evidence. Pre-resolved in `services.process_case.classify`, the detector receives a map; a network failure or guard rejection means the URL is simply absent from the map; `signals.urls.from_map` is the only rule: empty map = `None` (just `unresolved_shortener`, as if there were no network); map with other URLs = the missing one also carries `could_not_verify`. If the unroller isn't built, `None`, and the system behaves exactly as before.

**Observed (Oct 31):** `HEAD ma.sv/…` → 405; `GET` → 200, Kestrel, 2 bytes, NO `Location`: that link doesn't redirect from the server (expired, or redirects via JS/cloaking).

**What would invalidate it.** DNS rebinding: validated via one `getaddrinfo`, then `httpx` resolves again (a TOCTOU window) — low impact since the body is never read, but if it matters, the validated IP must be pinned at the transport layer. `getaddrinfo` doesn't respect the 1.5s budget, and httpx's `timeout` only caps each phase (connect, read) with whatever remains, not wall-clock total.

**Review notes (Oct 31).** `process_case.UNROLL` is a module-level global, set once at startup (`app.startup_unroller`, prod only): `classify`/`judge_case` are already at PLR0913's arity cap and the unroller doesn't vary per case; `measure.main` installs and restores it in a `finally`. `UnrollError` lives in the adapter since nothing outside `net` catches it by type.
