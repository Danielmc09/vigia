# ADR-065 · `user_explanation` only names deterministic signals; the analyst's stay in `Verdict.signals` (2026-10-27, Claude Code)

**Context.** Incident `adv-analista-senal-catalogo` (judge T-09, round 2). `verdict/build.py:_explanation` received deterministic signals plus the analyst's and named any that had an i18n key. The model could return `known_campaign` or `brand_off_domain` for "Hey auntie, can you lend me money?" (no link) and the user-facing text claimed "this matches an already-reported scam campaign, the link isn't from the official domain…" even with `label=legit`. The catalog filter (D-043) prevented free-text echo but still let the model choose which facts the code asserts (rules 5 and 14).

**Decision.** `build_verdict` passes `_explanation` only `softened` (the `Evidence.signals`, from rules). Without a deterministic signal, the text is the label's generic template. Analyst signals stay in `Verdict.signals` (panel, per D-060 the panel doesn't show their `type` either) and still move `action` and the impersonated brand only when they carry an exact `brand` from the country pack.

**Why.** The model must never choose what fact the code asserts to the user (rule 14); any citable fact has to come from rules, with a real `source`.

**What would invalidate it.** A deterministic analyst tool (e.g. `analyze_url`) returning signals that must be cited; then they enter `Evidence.signals` with a rules `source`, not via the model's output.
