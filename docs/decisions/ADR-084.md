# ADR-084 · Observability: structlog, prometheus-client and sentry-sdk; traces as `trace_id` in logs (2026-10-28, Claude Code)

**Context.** T-13b (specs/11) asks for JSON logs, `/metrics`, and Sentry.

**Options.** (a) stdlib `logging` with a hand-rolled JSON formatter and hand-rolled counters for `/metrics`; (b) the three libraries the spec names; (c) full OpenTelemetry.

**Decision.** (b), plus only the minimum of (c) specs/11 §1 actually requires: `trace_id` on every log of the same case, no OTel SDK.

**Why.** The spec names (b) by name; hand-writing Prometheus exposition format and a Sentry client is unreviewed code nobody checked; OTel adds 3+ packages for an exporter we don't have (Grafana Cloud "if there's time"). Sentry stays off with no `SENTRY_DSN` (no network in tests).

**What would invalidate it.** Railway or Grafana Cloud requiring OTLP for the video, or `sentry-sdk` leaking PII that `before_send` can't catch (A09 test first).

**Extension** (T-13b, decisions outside specs/11): stages/metrics in English (`gate|jev|rules|analyst|fusion|policy|reply`, `vigia_case_ms`…); media reading (Voice/Spark/SAM) and `ingest` count as `gate`. Metrics travel via a `ContextVar` (`telemetry.recording`) to avoid widening signatures; nothing is recorded outside it (evals). `route` comes from `Verdict.degraded` (obvious = no analyst). `/caso` counts with `business_id="eval"`. JSON logs only under `VIGIA_MODO=prod` (structlog console in dev). `/salud`: Jev checked only for reachability (<500, no key sent), Meta via `GET /models` with the key, 2s timeout. Sentinel: eval cases c-0001, c-0189, c-0145 (not a dedicated sentinel business), ceiling 5s text / 25s image/audio, alerts in Spanish, 15-minute dedupe per alert+case in a tempdir JSON file (ephemeral on Railway); ~$0.01/run, ~$1/day every 15 min. No email for P1, no hourly P3 grouping, no Redis/queue metrics (layer 2).

**Extension 2** (reviewer T-13b): logs and Sentry keep only the exception type, never the message or traceback (`telemetry._exception_type`, `before_send` strips `exception.values[].value`); `uvicorn*` loggers are rewired to root (no own handlers, `propagate=True`). Context: an exception's message can carry case text (names, phones the regex misses), and uvicorn printed "Exception in ASGI application" with a clear traceback outside the sanitizing handler.

**Options.** (a) scrub the traceback with regex; (b) type only.

**Decision.** (b): a regex can't see names, and location stays in Sentry's frames (no local variables).

**What would invalidate it.** An incident undiagnosable without the traceback; then traceback only in Sentry with `include_local_variables=False`, message still discarded.

**Extension 3** (judge T-13b): `/salud` is public and every call hit Postgres and Meta's `GET /models` (with the key) → cached 10s in-process (`HEALTH_CACHE_S`).

**Options.** (a) a token like `/metrics`; (b) a short cache.

**Decision.** (b): Railway and the sentinel call it with no credential, and 10s caps hammering to 6 checks/min per replica without hiding an outage longer than 10s. `OPERADOR_TELEFONO` validated as E.164 at startup (empty = no operator).

**What would invalidate it.** Several replicas behind a load balancer under real abusive traffic; then a per-IP cap at the edge.

**Deviation** (reviewer T-13b, specs/11 §2/§4): SLI-based alerts don't fire on their own. Cost over `ALERTA_PRESUPUESTO_USD`, Meta 429/5xx streaks, 2 webhook failures in 5 minutes, and degraded rate over 10% in 15 minutes all need state across requests and replicas (windows, streaks) — that's Redis, layer 2 (T-16). Today they're visible in `/metrics` and logs; the only automatic operator alert is the sentinel (verdict or latency on 3 canonical cases, every 15 minutes via T-19's cron), which incidentally catches Meta outages, exhausted credits, and a renamed model. RUNBOOK.md marks, per section, how each is detected today.

**What would invalidate it.** Redis arriving (T-16) or an incident the sentinel missed; then evaluate rules over `/metrics` (Grafana Cloud) before writing custom windows.
