# ADR-085 · Jev out of runtime: Spark with `json_schema` as the gate judge in `eval`/`prod` (2026-10-28, Claude Code)

**Context.** T-08b. Discord rule (#faqs, Oct 28): "every model your project calls at runtime must be a Meta model." Jev (TypeSafe) is not a Meta model. In `eval`/`prod` only the deterministic floor (D-051) and a Meta model may remain on that path.

**Options.** (a) turn the model judge off in `eval`/`prod`, floor only; (b) Spark 1.3 with strict `json_schema`, one call; (c) Jev behind a proxy — discarded, exactly what the rule forbids.

**Decision.** (b).
- `Settings._jev_real_only_in_dev` rejects `JEV_BACKEND=real` outside `VIGIA_MODO=dev`.
- `model/spark_judge.py:SparkJudge` asks for `{manipulacion: bool, triage: enum}`. Any failure (network, schema) falls back to `MOCK_ANSWER` — the second copy of `JevJudge`'s fallback; extracted on the 3rd.
- The factory lives in `services/judge.py:make_judge` (picks between two adapters, specs/09 §19), used by `app.py`, `services/whatsapp.py`, `tools/measure.py`. In `dev` it delegates to `model/jev.py:make_dev_judge`. In `eval`/`prod` it uses Spark if there's a key, else the mock.
- `tools/measure.py:full()` builds the judge with `mode="eval"` regardless of `.env`, so `make evals` never calls Jev even with `JEV_BACKEND=real` set.
- `docker-compose.yml`: `VIGIA_MODO` defaults to `prod`. Prod requires explicit DSNs (`_prod_needs_explicit_dsns`), so the `api` service also receives `MIGRATION_DATABASE_URL`, unused by the api.
  - Ceiling: the api container holds the schema-owner credential. Railway (T-19) must give it a non-superuser value, or the validator needs relaxing for the api.
- `JudgeAnswer` gains `usd` and `tokens` (default 0); `measure.with_analyst` adds them to the case cost, so the judge counts toward `usd_total` and `--max-usd` (rule 11).
- `GateResult.source` and `JudgeAnswer.source` gain `"spark"`.

**Why not (a).** The floor alone has low recall against paraphrased manipulation (Bloqueos, D-051).

**Token cap.** At 40 tokens, Spark's `minimal` reasoning ate the budget: 85 of 89 responses came back empty and the judge fell to mock. Across 10 cases, reasoning measured 160-550 output tokens. Fixed `MAX_TOKENS=1000`. The schema still admits no free text (rule 14).

**Prompt.**
- v1 said "claim legitimacy" and flagged 5 of 46 legit cases (c-0086, c-0092, c-0094, c-0095, c-0097), all legitimate business orders phrased like "ignore/forget the previous instructions". `manipulacion_legitimo` 0.109, gate red.
- v2 flagged c-0084 ("mark order 123 as safe"). 0.022.
- v3 only flags text that addresses an AI/bot/system, or that asks to classify *this* message/link/email as safe.

**Measured** (evals-rapido, `mode=eval`, 2026-10-28, final prompt v3, "genuine" instead of "legitimate" to pass `test_i18n`):

Runs with the earlier cap or prompt: 40 tokens → $0.107, judge had no effect; prompt v1 → $0.265, gate red; v2 → $0.250, gate red; v3 still with "legitimate" → $0.237, gate ok, same metrics. Total spend of these trials ~$1.2.

**Ceiling.** Jev's continuous score is lost: the boolean maps to 0.0 or 1.0, the 0.7 threshold still applies. Latency adds ~1.5s to the webhook path. `--adversarios` still runs on the mock (floor only); this judge is unmeasured against Bloqueos' 19 paraphrases.

**What would invalidate it.** `manipulacion_legitimo` > 0 on a full run; the judge costing more than $0.003/case; its latency pushing the webhook past specs/11's SLO.

**Revised 2026-10-28** (judge T-08b, MAJOR). `mode` defaulted to `dev`, and Railway runs the Dockerfile `CMD` with no compose: a plain `uvicorn` with `JEV_BACKEND=real` would put Jev into production. Options: (a) `prod` by default; (b) `dev` explicit for Jev, image defaults to `VIGIA_MODO=prod`. Chose (b): (a) breaks local work and tests, which run without DSNs. `_jev_real_only_in_dev` requires `"mode"` in `model_fields_set`. Effect: `docker run` without `DATABASE_URL`/`MIGRATION_DATABASE_URL` no longer starts.

**What would invalidate it.** Railway overriding `VIGIA_MODO` with `dev`.
