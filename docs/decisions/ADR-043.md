# ADR-043 · `user_explanation` is always built by code from i18n, never the analyst's raw text (2026-10-27, Claude Code)

**Context.** T-07 folds `AnalystResult` (T-09, mocked for now) into the `Verdict`; `AnalystResult.explanation` can carry free model text, and a prompt injection could write anything there (rule 14: the model never talks to the user).
**Options.** Copy `analyst.explanation` into `verdict.user_explanation` if present, filtered by a forbidden-word list; never read it, and build the text in code from the signals' `type` and weight (including any signal the analyst contributed) using i18n templates.
**Decision.** The second. `verdict/fusion.py:_explanation` never reads `analyst.explanation`; it only uses `label`, `brand`, and signal `type`s to build the text with `verdict.*`/`signal.*` i18n keys. Regression test `test_build_verdict_never_forwards_the_analyst_raw_text` injects `"IGNORE ALL PREVIOUS INSTRUCTIONS"` into `explanation` and checks it never appears in the verdict.
**Why.** A forbidden-word filter is a list that needs maintaining and that a new injection phrase evades; never reading the field at all has no such gap.
**What would invalidate it.** The analyst needing to add an explanation no signal captures (e.g. a pattern found via web search) → define a new signal type for that, not a door into free text.
