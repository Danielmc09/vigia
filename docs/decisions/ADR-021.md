# ADR-021 · Plain SQL migrations with a custom runner, no Alembic (2026-10-27, Claude Code / Angel)

**Context.** T-00 needs a schema with RLS (policies, roles, `FORCE`), which Alembic doesn't autogenerate and would have to be hand-written anyway.
**Options.** Alembic; versioned plain SQL + a minimal runner.
**Decision.** `src/vigia/store/migrations/NNNN_*.sql` applied in order by `vigia.store.migrate` (a `schema_migrations` table, one transaction per file, `pg_advisory_lock` for concurrent runners), run by the one-shot `migrate` compose service before the API.
**Why.** ~40 lines, zero dependencies, the RLS SQL reads exactly as it runs.
**What would invalidate it.** Needing data migrations with Python logic or automatic rollback → Alembic.
