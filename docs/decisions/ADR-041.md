# ADR-041 · Known campaigns travel inside the country pack; official domains and shorteners never match (2026-10-27, Claude Code)

**Context.** `detect(case, pack, suppliers, resolver)` already has 4 parameters (specs/09's cap, ruff `PLR0913`), and the knowledge base is per country, like the pack. The seed is written by another agent from public alerts, which often name the real site ("only use bancolombia.com") or a shortener.
**Options.** A fifth parameter with `noqa`; a new context object; a `campaigns` field on `CountryPack`, outside the JSON, attached by whoever loads the base (`signals.knowledge.with_campaigns`: a file in evals/tests, the `known_campaigns` table in the app).
**Decision.** The third. Domain matching ignores hosts whose registrable domain is official in the pack or is in `SHORTENERS`. The table is global, no `business_id`, no RLS, only `GRANT SELECT` to `vigia_app`, and no free-text column (D-017: only indicators cross between businesses).
**Why.** Zero new parameters, and the pack is already "everything country-specific the signals need"; without the filter, an alert that names the official domain would turn every legitimate message from that bank into a hard scam.
**What would invalidate it.** A base that stops being per-country (global campaigns) → its own context object.
