# ADR-023 · The app connects with a role that has neither superuser nor BYPASSRLS (2026-10-27, Claude Code / Angel)

**Context.** The official image's `POSTGRES_USER` is a superuser and bypasses RLS even with `FORCE ROW LEVEL SECURITY`.
**Options.** Connect as superuser and `SET ROLE`; two login roles.
**Decision.** `vigia_app` (`NOSUPERUSER NOBYPASSRLS`, created by `docker/postgres-init/01-app-role.sh` with `APP_DB_PASSWORD`) for the API; the superuser only in the `migrate` service's `MIGRATION_DATABASE_URL`. Policy via `NULLIF(current_setting('app.business_id', true), '')::uuid`: no context, zero rows.
**Why.** With `SET ROLE` an injection could `RESET ROLE`; with a separate role there's nowhere to go back to. `tests/test_store.py` checks the role attributes and `tests/test_owasp.py` checks isolation.
**What would invalidate it.** Nothing. Pending for T-19: on Railway the role is created by hand once (no initdb there).
