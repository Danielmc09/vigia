# ADR-090 · The panel form uses Spark when a key exists; 4000-character cap (2026-10-30, Claude Code)

**Context.** D-089 left the form degraded. Angel decided (Oct 30) it should use the same analyst as the webhook when `MODEL_API_KEY` exists. T-22d's reviewer and judge flagged that neither the form nor `/caso` had a length cap.

**Options.** (a) make `/caso` use Spark too — it's anonymous, anyone could spend credits. (b) only the form, which sits behind the token: `_form_analyst(config)` builds the same `spark_analyst` as the webhook, text only, no address book or SAM since the business is throwaway; `analyst or _form_analyst(config)` lets tests inject their own. With no key it shows "Rules only".

**Decision.** (b). `/caso` still only uses the injected `analyst`, `None` in production. `MAX_CASE_CHARS = 4000` applies to `CaseRequest.text` (`Field(max_length)`) and to the form POST; over the limit → 422. `_panel` returns an `APIRouter` to stay under 4 args (PLR0913). `render_panel` takes a `TryForm`.

**What would invalidate it.** A legitimate forwarded message over 4000 characters (e.g. a long email) needing a higher cap or truncation; the panel being exposed without a token.
