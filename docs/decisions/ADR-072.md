# ADR-072 · Cross-business operator panel: PII-free plain columns + SECURITY DEFINER readers (2026-10-27, Claude Code)

**Context.** specs/07 asks for a panel with the latest verdicts across all businesses; the app runs as `vigia_app` under RLS (`app.business_id`) and the full verdict is encrypted per business (`payload_enc`, specs/16).

**Options.** (a) decrypt per business with its DEK and assemble the view; (b) a separate role with BYPASSRLS; (c) plain non-PII columns on `verdicts` + definer functions that never return `business_id` or `payload_enc`.

**Decision.** (c). Migration `0007_panel.sql`: `kind`, `brand`, `confidence`, `signal_types[]`, `tools[]`, `usd`, `latency_ms`; `vigia_panel_verdicts(p_limit)` (cap 200) and `vigia_panel_today()` (since midnight America/Bogota), `SECURITY DEFINER SET search_path = public, pg_temp`, `REVOKE PUBLIC`, `GRANT vigia_app`. `store.save_verdict` writes the sealed verdict and these columns: signal types only from deterministic sources (never the analyst's, per D-060), deduplicated tools, `usd` = sum of `tools_used`. `brand` comes from the country pack via fusion, never free text, and is still escaped. Type `VerdictRow` in `domain/verdict.py`.

**Why.** Avoids per-view decryption (would put the KEK in the read path) and avoids a role that bypasses RLS wholesale.

**What would invalidate it.** One of these columns turning out to identify a person or business (e.g. a rare brand unique to one client).

**Revision** (reviewer T-13): metrics come from `Settings.panel_metrics` (`VIGIA_PANEL_METRICS`, default `evals/ultimo.resultado.json`, relative to the image's working dir `/app`); `.dockerignore` excludes `evals/*` except `ultimo*.resultado.json`, and the `Dockerfile` does `COPY evals ./evals`. `PANEL_ROWS = 50` in `app.py`; panel language is fixed `LANG = "en"` (single operator; per-operator with T-17b). `verdicts_today` returns a raw `dict[str, int]`, not `Label`.
